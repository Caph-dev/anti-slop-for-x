# Anti Slop for X

在 X（x.com）上按上下文判断帖子内容的质量，用可核对的原文证据标记可疑内容；不判断内容是不是 AI 写的，也不会按模型结果自动折叠或自动屏蔽账号。

[English](README.en.md) · [CHANGELOG](CHANGELOG.md) · [架构说明](docs/architecture.md)

已发布版本 v0.9.0。本文描述的 issue #3 改动尚未发布，需要从当前源码构建才能试用；旧版 release 的行为不同。目前只构建 Chrome MV3，完整浏览器扩展流程尚未验证，也未上架 Chrome Web Store。

## 目录结构

```
extension/  Chrome MV3 扩展，WXT + TypeScript
worker/     0.1.0 时代的本机代理，扩展已不再调用
docs/       架构、分类标注指南、离线评估、旧版代理、隐私政策
ROADMAP.md  计划中与暂时关闭的功能
```

## 它怎么工作

1. content script 读取时间线上已经渲染的内容，只提取页面自己能证明的上下文：本帖正文，以及包含在同一条 article 里的引用帖。父帖和串首都无法从页面证明，因此不会被读取。
2. 发送前先在本地做准入判断：总开关、扫描范围、不发送偏好、你的规则、配置缺项、缺失的必要上下文。任一条件不满足就不发送，并记录原因。
3. 全部通过时，background 只向支持结构化输出的 OpenAI Responses 端点发一次请求。模型必须给出类别、理由，以及从被引来源逐字复制的证据；扩展在本地把证据与页面文本按规范化后比对，引不到原文就整条判为失败（`invalid_provenance`），不发第二次请求。
4. 结果按当前模式呈现：**仅标记**给出带证据的标记；**仅记录**只写进本标签页记录，不改动页面。折叠只有两个来源——你的隐藏规则，或你自己点「折叠」。

判定轴是**给定上下文里的内容质量**，不是作者身份。短、带情绪、口语、正式、非母语、中日韩文本本身都不构成任何类别，风格也不能当作来源证据。类别定义与标注流程见 [docs/content-taxonomy.md](docs/content-taxonomy.md)。

扩展不含密钥，也不中转流量。你填自己的 endpoint 和 key，请求由 background service worker 直接发往该地址。

## 安装

以下 release 安装步骤适用于已发布版本，其功能与本文所述的未发布改动不同。要试用本分支，参见[开发](#开发)。

1. 打开 [Releases](https://github.com/Caph-dev/anti-slop-for-x/releases)，下载已发布版本的 zip 资产。
2. 解压到一个固定的目录，比如 `~/Extensions/anti-slop-for-x`。
3. 打开 `chrome://extensions`，启用开发者模式。
4. 点「加载已解压的扩展程序」，选择解压后的目录。
5. 打开扩展选项页，配置该发布版本支持的 endpoint 和 key。v0.9.0 不支持 OpenAI Responses。
6. 打开任意 x.com 页面，点工具栏图标，确认面板能打开。

升级时下载新 zip，解压覆盖同一个目录，再到扩展页点一次刷新按钮。目录换了位置，Chrome 会把它当成另一个扩展，所以保持路径不变。

从源码构建的步骤见[开发](#开发)。

## 配置本分支

只有 **OpenAI Responses** 协议能返回可核对的证据，因此只有它能发送请求。预设决定 Base URL、路径和协议，选预设时这三项锁定；Model 始终可改。

| Endpoint | Base URL | Path | Protocol | 默认 Model |
|---|---|---|---|---|
| OpenAI Responses（官方） | `https://api.openai.com/v1` | `/responses` | `openai-responses` | 无，必须自己填 |
| TypeSafe / Jev（旧版，不发送） | `https://api.typesafe.ai/v1` | `/systemone` | `jev` | `jev-latest` |
| OpenAI Decisions（旧版，不发送） | `https://api.openai.com/v1` | `/decisions` | `openai-decisions` | `gpt-6-luna` |
| Custom endpoint | 你填 | 你填 | 你选 | 你填 |

Jev 与 Decisions 两个预设为兼容旧设置保留，但选中时不发送任何内容：选项页和 popup 会直接说明「该协议无法返回可核对的证据，请选择 OpenAI Responses」。扩展不会把这类设置自动换成另一个端点，也不会绕过检查调用它。

Responses 没有默认模型。模型名留空就等于「不发送任何内容」，选项页会明确提示。

选中预设时对应的 origin 已在 `host_permissions` 中，保存不会弹权限窗。选 Custom 并换到其他域名时，保存或测试会在点击手势里请求该 origin 的权限；拒绝授权后请求失败，重新保存可以再申请。如果你已经存了 key，而这次改动会把它用在**新的 origin** 上，扩展会先弹确认，你同意后才继续。

key 保存在 `chrome.storage.local`，运行时会被扩展读入内存，只发往你选的 Base URL。能读你 Chrome profile 目录的本机进程仍能取到明文 key，任何把密钥存在浏览器里的方案都有这个限制。

### 测试连接

「测试连接」只发送一条**为本功能编写的合成帖子**（`Reply YES and follow me to get the secret free-flight list!`），不读页面上的任何内容。它要求扩展与模型调用均已启用并保存，且当前端点配置无问题、目标 origin 已授权；设置改动后需要重新测试。

## 两个模式

选项页和 popup 的 Mode 决定结果怎么呈现。

| 模式 | 命中时 | 会改你的 X 账号 |
|---|---|---|
| 仅标记 Manual | 显示类别与可核对证据，内容不隐藏；由你决定 | 否 |
| 仅记录 Shadow（默认） | 只在「本标签页记录」里计数，页面完全不动 | 否 |

没有任何模式会按模型结果自动折叠内容或自动屏蔽账号，也没有启动开关。用户自己的隐藏规则仍可自动本地折叠；模型自动折叠与自动屏蔽要等独立冻结评估支持后另行发布。旧设置里的「自动折叠 / 严格」仍然可读，但按仅记录运行，直到你自己重新选模式。静音和屏蔽只在你点击时执行。

旧版的分数阈值（`threshold`）保留在存储里，识别路径不读它。

## 界面

工具栏图标打开 popup，显示当前端点、模型、模式、扫描范围和状态，并提供「扫描当前页」「模型与更多设置」以及「本标签页记录」。扫描结束会报告检查了多少条，没有可检查内容时说明原因。

### 标记与折叠

命中的帖子在正文上方插入一条整行宽的卡片：

```text
疑似诱导互动   [折叠] [判断有误] [始终保留] [静音] [屏蔽] [依据]
```

- 卡片里的「依据」列出被引用的原文、反证，以及模型自己的解释（解释未经验证）；引文已经和页面文本比对过，判断本身仍可能错。
- 「判断有误」只在本标签页里撤掉这条标记并计数，不发送任何东西，也不改你的规则。
- 「始终保留」把这个账号加入保留名单：不再标记、不再隐藏、也不再发送它的内容。
- 编辑保留或隐藏名单时，每行填写一个账号用户名，只能包含 1–15 个字母、数字或下划线，匹配不区分大小写。旧版非空无效条目会保留并提示，直到你修正或删除。超过 5,000 条的旧名单可以分批缩小，每次保存最多修改 5,000 个不同账号。
- 你自己点「折叠」后，卡片上的「展开」随时恢复。
- 你设为隐藏的账号会被折叠成本地卡片。折叠永远可以从卡片展开，且规则继续生效；如果你正在阅读这条内容，它只被标记、不会被折叠（见下）。
- 调试模式下被检查的帖子显示诊断徽标；你的隐藏规则仍然生效，并可显示可逆卡片。

### 阅读保护

正在屏幕上的帖子，以及已经在屏幕上停留超过 600ms 后被划走或你展开过的帖子，都不会被折叠——需要折叠时改为标记。你自己点的折叠 / 展开不受影响。

### 静音与屏蔽

沿用 X 自己的术语，只在点击时执行。

| 操作 | 效果 |
|---|---|
| 静音 Mute | 你不再看到这个账号的推文，对方不会收到通知，仍能关注你 |
| 屏蔽 Block | 对方无法关注你或与你互动，你也看不到对方 |

手动静音和屏蔽优先点 X 原生「···」菜单，失败再走同登录态下的 web API。无界面环境里原生菜单点不到，需要在真实浏览器会话中使用。

## 什么情况下不发送

以下条件都在本地判断，命中就不发请求。设置在发送前重查；已经发出的内容无法撤回。

- 总开关关闭，或帖子不在扫描范围内。
- **模型调用关闭**（设置字段 `prefilterOnly`）：不向任何模型发送内容，手动扫描、调试模式和「测试连接」也一样。这里没有本地关键词兜底，内容只是不被检查。
- **短帖偏好**：旧版本默认跳过短帖，所以升级上来的设置会保留这一不发送偏好；全新安装默认不跳过。它是隐私与费用偏好，不是质量判断。
- **不发送我自己的帖子**（默认开启）。页面上读不到当前账号时同样不发送，并记为「无法确认当前账号」。
- 账号在保留名单里（保留名单优先于隐藏名单）。
- 在「仅标记」模式下，账号在隐藏名单里会本地折叠或受阅读保护而仅标记；该内容不发送。
- 配置问题：协议不是 Responses、没有 key、没有模型、URL 不可用（必须是 https，仅 localhost 允许 http，且不能带账号密码、片段或路径跳转）、缺少该 origin 的站点权限。
- 必要上下文不完整（见下）。

## 调试与本标签页记录

调试模式在 popup 里打开，覆盖 autoScan（用于只读诊断），但仍然遵守总开关、扫描范围、不发送偏好、保留与隐藏规则，以及上面的所有不发送条件。仅记录模式下不注入徽标：影子结果只出现在 popup 的记录里。

「本标签页记录」只存在 content script 的内存中，刷新或关闭标签页即消失，不写存储、不跨标签页。内容包括每条帖子的状态与原因码、模型请求尝试次数、平均响应时间、自动模型策略会折叠的目标条数，以及你标为「判断有误」的次数。模型自动折叠仍关闭。去重按页面上的帖子 ID，不按文本；记录里不含原文、账号、密钥或模型说明。

## 目前无法证明的事

这些是当前实现的真实边界，不要当成已经解决的问题：

- **父帖与串首无法证明。** 扩展不会把相邻帖或焦点帖猜作父帖，也不抓链接或读作者历史，因此普通回复的 `parent` / `root` 是「缺失」或「未知」。`generic_irrelevant` 和 `content_free_restatement` 需要完整父帖或可证明的引用帖作为对照。没有这种上下文时会弃权，因而普通回复的比较类覆盖有限。
- **媒体与截断文本一律弃权。** 带图片、视频、GIF、链接卡片、投票，或被「显示更多」截断的帖子，上下文只能是「不完整」，因此不发送、记为上下文不完整。这会让大量正常帖子根本没有被检查。
- **仅回复模式依赖页面上可见的「Replying to @」表头**，表头缺失的回复会被漏掉。
- **无法确认当前账号时**（未登录、侧栏 profile 链接缺失），「不发送我的帖子」默认开着，于是同样不发送。

## 验证状态

- 没有自然/困难分层的标注数据集，也没有独立冻结评估。`scripts/evaluate-issue3.mjs` 只会做输入校验与机械检查，并且**永远拒绝发布授权**；manifest 声明、哈希或合成夹具都不能代替独立评审。
- 单元测试使用合成夹具，只覆盖代码路径与不变量（准入、证据校验、模式决策、阅读保护、诊断计数等）。**它们不证明分类质量，也不证明在真实 X 上的正确性。**
- 未在真实 X 页面上验证提取与呈现，未用真实 provider key 做端到端调用，未在真实浏览器扩展环境里跑过完整流程。
- 先前构建曾在真实浏览器的本机合成页面上，用模拟 Chrome API 检查扫描、影子模式、可逆折叠和过期结果。共享浏览器代理已断开，最终构建未重测；这些检查都不能证明实际扩展环境或真实 X 的行为。

## 已知限制

- 只保证 Chrome MV3。WXT 结构便于以后加 Firefox，但尚未适配。
- 未上架 Chrome Web Store，安装靠 release 里的 zip。
- 同一请求快照在同一页面会复用在途请求或缓存；不同上下文是不同请求，仍可能产生多次调用。
- 扩展只做本地呈现与规则；除你点击的静音/屏蔽外不写你的 X 账号。
- `worker/` 是 0.1.0 时代的代理，扩展已不再调用，说明见 [docs/legacy-proxy.md](docs/legacy-proxy.md)。

## 开发

从源码构建需要 Node.js 20.19 或更高的 20.x 版本，或 Node.js 22.12 及以上；当前使用的锁文件包含这些依赖约束。

```bash
npm install
npm run unpacked
```

`npm run unpacked` 先构建，再把产物镜像到 `unpacked/chrome-mv3`，Chrome 加载这个目录。试用本未发布分支时，在选项页选择 OpenAI Responses 并填写 endpoint、模型和 key。改完代码重跑这条命令，再到扩展页点刷新。

| 命令 | 作用 |
|---|---|
| `npm run dev` | WXT 开发模式 |
| `npm run build` | 构建到 `extension/.output/chrome-mv3` |
| `npm run unpacked` | 构建并镜像到 `unpacked/chrome-mv3` |
| `npm test` | 单元测试 + 离线评估脚本测试 |
| `npm run typecheck` | TypeScript 类型检查 |
| `npm run zip` | 产出扩展 zip，WXT 原生命名 |
| `npm run release:build` | 类型检查、测试、zip、镜像未打包目录、把 zip 命名为 `v<版本>.zip` |

离线评估工具只接受元数据输入（不含原文），用法与限制见 [docs/issue3-evaluation.md](docs/issue3-evaluation.md)。
